Pace is designed from the ground up for safe, efficient multithreaded execution. Normal developers should not need to manually manage OS threads. Pace provides high-level abstractions like `async`/`await`, `spawn`, and `actor`s to handle concurrent work effortlessly.

## The Concurrency Model

Pace provides several tools for different concurrency needs:
- `async` / `await` -> Asynchronous suspension
- `spawn` -> Parallel work
- `actor` -> Isolated mutable state
- `Channel` -> Message passing
- `Atomic` & `Mutex` -> Advanced synchronization

## Async / Await

The `async` keyword marks a function that can suspend its execution without blocking the underlying OS thread. You use `await` to wait for an asynchronous operation to complete.

```pace
async fn fetchUser(id: int) -> User {
    let response = await http.get("/users/{id}")
    return response.json()
}
```

To call an `async` function, you must `await` it:

```pace
let user = await fetchUser(id: 42)
```

> [!NOTE]
> `async` means the function can suspend; it does not mean a new OS thread is created. The Pace runtime schedules `async` work across available threads.

## Multithreading with `spawn`

To run heavy computations in parallel, use the `spawn` block. The Pace runtime will schedule this work across its thread pool.

```pace
spawn {
    heavyWork() // Runs in parallel
}
```

## Actors (Isolated State)

Sharing mutable state across threads is notoriously dangerous and leads to data races. Pace solves this with **Actors**. 

An `actor` isolates mutable state. It guarantees that only one task can access its state at a time, making concurrent access perfectly safe without the need for manual `Mutex` locking. More importantly, **Actors are the foundation of Multi-Threading in Pace.** 

When you instantiate an actor and send it a message (by calling a method), that method call is pushed to a background thread pool managed by **libuv**. The actor processes messages sequentially, but multiple actors can run in parallel across all available CPU cores.

```pace
actor Counter {
    count: int

    init() {
        self.count = 0
    }

    fn increment() {
        self.count = self.count + 1
    }

    fn get() -> int {
        return self.count
    }
}
```

Because an actor's state is isolated, you must `await` its methods from the outside to ensure safe asynchronous access:

```pace
let counter = Counter()

// These calls are dispatched to a multi-threaded worker pool
await counter.increment()

let value = await counter.get()
println(value)
```

By combining single-threaded `async`/`await` for I/O operations and multi-threaded `actor`s for CPU-heavy tasks, you can build highly concurrent applications that are immune to traditional data races!
