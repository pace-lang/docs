Whether you're a seasoned systems engineer or a beginner looking for an intuitive programming language, Pace was built for you. We've completely reimagined what a modern, statically typed language should feel like, combining high-performance execution with developer-first ergonomics.

---

## What is Pace?

**Pace** is a modern, statically typed, **pure Ahead-Of-Time (AOT) compiled** programming language designed to be intuitive, safe, and blazingly fast. It stands entirely on its own, powered by a native Cranelift backend.

At its core, Pace is built on three pillars:

1. **Safety**: Strict, compiler-enforced null safety (`T?`) prevents entire classes of runtime errors. You'll never see a `NullPointerException` again.
2. **Predictable Performance**: Pace uses deterministic Automatic Reference Counting (ARC) instead of a tracing garbage collector, guaranteeing memory safety without unpredictable pause times.
3. **Expressiveness**: First-class support for Object-Oriented (Classes, Interfaces) and Functional (Generic Algebraic Data Types, Pattern Matching) paradigms.

## 🚀 Core Language Features

### The Modern Mutability Model

Pace optimizes for real-world ergonomics. Variables are **mutable by default** using the `var` keyword. To declare immutable bindings, you simply use the `let` keyword. For compile-time constant primitives, use `const`.

```pace
var name = "Pace Developer" // Mutable string
let version = "0.1.0"  // Immutable string

// The compiler enforces immutability!
// version = "0.2.0" // ❌ COMPILER ERROR
```

### Generics & True Monomorphization

Pace features a robust generics system, powering **true monomorphization** for functions, classes, and enums. When you use `Result<T, E>` or a generic class, the compiler generates a unique version of that type for each type argument. This completely eliminates the need for boxing or opaque pointers, leading to zero-cost abstractions, massive execution speed improvements, and full C-FFI compatibility for generic structs!

We have officially introduced **Standard Generic Algebraic Data Types**, including `Option<T>`, `Result<T, E>`, `List<T>`, and `Map<K, V>`.

### Pattern Matching (`match`)

To complement ADTs, Pace supports comprehensive pattern matching via the `match` expression! You can safely unwrap variants and extract payloads with compile-time exhaustiveness checking. Furthermore, you can explicitly pattern match on generic ADT variants using the new generic pattern matching syntax to ensure absolute type safety.

```pace
var result: Result<Int, String> = fetch_data()
match result {
    Result<Int, String>::Ok(data) => print("Success: \{data}")
    Result<Int, String>::Err(e) => print("Failed with error: \{e}")
}
```

### The `?` Error Bubbling Operator

Dealing with `Result<T, E>` is frictionless. The postfix `?` operator elegantly unpacks the `Ok` payload or returns early with an `Err`.

```pace
func fetchAndProcess(): Result<String, Error> {
    var data = fetch()? // Returns early if fetch() fails!
    return Result.Ok(process(data))
}
```

### Value Types (`struct`)

You can define highly efficient, stack-allocated, non-ARC value types using the `struct` keyword! Structs guarantee pass-by-value semantics and explicitly forbid ARC-managed fields, giving you fine-grained control over memory layout.

### String Interpolation

Pace now supports string interpolation using both `\{expr}` and `${expr}` syntax. Expressions are directly evaluated and safely concatenated inside string literals—no manual type conversions necessary!

```pace
var name = "Pace Developer"
print("Welcome to v0.1.0, \{name}!")
```

### Function Overloading

The compiler now supports function overloading via a custom name mangling system. Developers can declare multiple functions with the same name, so long as their parameter signatures differ!

### Null-Safety Operators

Dealing with optional data is now frictionless. We've introduced full support for the null-coalescing operator (`??`) and the null-coalesce assignment operator (`??=`). This allows you to easily provide default fallbacks for `T?` types.

### Type Aliases

You can now define type aliases using the `type` keyword. They are completely transparent to the compiler but drastically improve the readability of your code and diagnostic messages!

```pace
type StatusCode = Int
type UserId = String
```

### Generic Interfaces

Classes can now formally implement generic interfaces, and the typechecker will properly validate them (e.g. `class MyCollection implements Iterable<T>`). We also lowered `for` loops to natively use `.iter()` and `.next()` under the hood, natively integrating with these interfaces.

### Custom Destructors (`deinit`)

Classes can now define a custom `func deinit()`. The compiler dynamically tracks this function and automatically invokes it right before the object's reference count drops to 0 and its memory is freed. Perfect for closing files, network sockets, or releasing resources!

### Access Modifiers & Constructor Checks

- **Access Modifiers**: We've introduced explicit `public` and `private` keywords, dropping the legacy underscore (`_`) convention for visibility control.
- **Constructor Checks**: The typechecker now rigorously tracks uninitialized properties inside class constructors, producing robust compile-time errors if you attempt to use a partially initialized object.

## 🏗️ Standard Library & Architecture

### The Dynamic Standard Library

We have successfully decoupled standard types from the core compiler. The standard library has been expanded to include powerful new modules for real-world application development:
- **Collections**: Fully typed `List<T>`, `Map<K, V>`, `Set<T>`, `Queue<T>`, and `TreeSet<T>`.
- **File System (`std:fs`)**: Perform IO operations using `fs_readText`, `fs_writeText`, and `fs_exists`.
- **Networking (`std:http`)**: Native `http_get` support for external API calls.
- **Strings (`std:string`)**: Comprehensive string manipulation methods like `string_replace`, `string_substring`, etc.
- **Math (`std:math`)**: Provides `Math.Pi`, `Math.abs()`, etc.

Collections like `List` and `Map` are **native-backed**, utilizing highly optimized implementations over a C-ABI bridge.

### Pure AOT Compilation (Goodbye VM!)

Pace is now a **pure Ahead-Of-Time (AOT) compiled language**. When you execute `pace run`, it compiles your code into a lightning-fast native executable and seamlessly spawns it, dropping the interpreter overhead entirely.

### Local Module Resolution

We've overhauled the module loader! Imports like `import "math_utils"` now successfully resolve if `math_utils.pace` exists in your local directory. No more fighting with explicit relative paths or package configurations for simple sibling modules.

## 🛠️ Tooling & Ecosystem

### Built-in Style Linter

Pace introduces a brand new, highly opinionated style linter built directly into the compiler pipeline. It intelligently enforces the Pace design philosophy (`camelCase` for functions and variables, `PascalCase` for types and constants, `static` members on classes) without failing compilation for perfectly valid code. 

### Ergonomic Project Creation

The `pace create <name>` command provides helpful step-by-step instructions so you can jump into coding immediately. We've also locked down package naming conventions to enforce ecosystem consistency: `pace create` and `pace init` strictly require project names to use `kebab-case`.

### Seamless CLI Upgrades & Diagnostics

- **Seamless Upgrades**: You can update your Pace installation directly from the terminal by running `pace upgrade`.
- **Upgraded Diagnostics**: CLI-level project errors (e.g., missing `main` function, linker issues, missing `pace.toml`) are now beautifully styled global diagnostics (like `[E001]`). If a required system C compiler is missing, the linker prints the exact terminal commands needed to install it.

### Optimized Release Builds

The `pace build` and `pace run` commands now officially support the `--release` flag! Running in release mode automatically leverages optimizations (`speed_and_size`) and strips debug symbols during the linking phase, radically shrinking the size of your compiled binaries and producing a lightning-fast executable.
